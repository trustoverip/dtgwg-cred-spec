[[def: Trust Tasks core specification, core specification]]

~ The core specification of the Trust Tasks stack: the [trust task](https://glossary.trustoverip.org/#term:trust-tasks) document envelope, the consumer processing rules, the declarations every individual Trust Task specification must make (parties, proof requirements, side effects, error codes), error responses, and the version scheme. Individual Trust Task specifications — the per-task registry entries this specification calls "qualifying" when they meet the [Trust Task Context Binding](#trust-task-context-binding) profile — are conforming refinements of the core specification; transport bindings map its documents onto concrete transports.

~ This specification's normative references are to the core specification as published by the DTGWG Trust Tasks Task Force ([SPEC.md](https://github.com/trustoverip/dtgwg-trust-tasks-tf/blob/fbe196a8a17ba3f99d0657a64be5ac58621023a1/SPEC.md), version 0.4 per its Appendix B changelog — the header at that commit still reads 0.3 — commit `fbe196a`). That document calls itself "the Trust Tasks framework", which is why its version labels read "framework 0.4" and every Trust Task specification's front matter declares a `targetFrameworkVersion`; this specification quotes those labels as published. Should the working group advance a coordinated DTG Core Trust Tasks specification, a future revision of this specification may re-point the term to it.

~ The term names a technical specification — not a [governance framework](https://glossary.trustoverip.org/#term:governance-framework) in the ToIP sense; where this specification means a governance framework, it says so.
